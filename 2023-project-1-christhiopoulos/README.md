### Documentation

Συμπληρώστε εδώ __όσο documentation χρειάζεται__ ώστε οι βαθμολογητές να
κατανοήσουν πλήρως τις λύσεις σας και να τις βαθμολογήσουν ανάλογα. Αυτό θα
πρέπει να γίνει ανεξάρτητα με το αν ο κώδικάς σας είναι καλά σχολιασμένος,
πράγμα που συνιστάται.

Στην εργασια μου εχω υλοποιησει το παιχνιδι που ζητηται,εχοντας συμπληρωσει ολα τα ερωτηματα.Εχω υλοποιησει τα .h αρχεια,την state.c,την state_alt.c,την set_utils.c,το interface.c και τελος το game.c που περιεχει την συναρτηση main.Eχω βαλει σχολια σε ορισμενα σημεια, που ισως δεν ειναι ξεκαθαρο το σκεπτικο μου πισω απο τις εντολες.Κυριο μερος της εργασιας μου ειναι η συναρτηση state_update,η οποια καλειται 60 φορες το δευτερολεπτο,καθοριζοντας τον τροπο που εξελιζεται το παιχνιδι σε καθε frame οπου με τη βοηθεια συναρτησεων απο την βιβλιοθηκη raylib δημιουργειται ολο το user interface.Σημεια που ειναι αξια προσοχης ειναι το vector remove της ασκησης 3 οπου εχω τοποθετησει το στοιχειο,που θα γινει remove, στο τελος του vector και μετα εκανα vector_remove_last.Επισης στο ερωτημα 5 εχω χρησιμοποιησει τις συναρτησεις απο το ερωτημα 4 ,ετσι ωστε οι ελεγχοι της state update να ειναι πιο συντομοι.Eπισης στο tests/state_tests.c υπαρχουν καποια test ωστε να ελεγχθει η λειτοργια των συναρτησεων.Επισης στο interface.c,σε καποιες συναρτησεις απαιτειται η μετατροπη συντεταγμενων του παιχνιδιου σε συντεταγμενες οθονης,για αυτον τον λογο εχω ορισει καποιο offset,ετσι ωστε να γινεται η μετατροπη πιο ευκολα.Τελος,εχω αλλαξει μερικα νουμερα για την κατασταση falling της μπαλας επειδη πιστευω πως ετσι ειναι πιο smooth το παιχνιδι.
